**analytics.ts:**
Create `src/lib/analytics.ts` with a type-safe `trackEvent()` function:
```typescript
declare global {
  interface Window {
    dataLayer?: Record<string, unknown>[];
  }
}

export function trackEvent(eventName: string, params?: Record<string, string | number>): void {
  if (typeof window === 'undefined') return;
  if (!window.dataLayer) return;
  window.dataLayer.push({ event: eventName, ...params });
}
```

This pushes events to GTM dataLayer. GTM Consent Mode v2 (wired in Phase 6) handles gating — events always push, but GA4 only processes them when consent is granted.

**ContactForm.tsx — generate_lead event:**
- Import `trackEvent` from `@/lib/analytics`.
- In the existing `useEffect` that watches `state.success` (the one that redirects to `/multumim`), add `trackEvent('generate_lead', { event_category: 'contact', event_label: 'contact_form' })` BEFORE the router.push redirect.
- This fires the GA4 `generate_lead` event when the contact form submits successfully, before navigating away.

**Note on CMPL-08 scope:** The requirement lists generate_lead, click_phone, click_whatsapp, scroll_depth. The `generate_lead` event is the critical one (fired on form success). Phone/WhatsApp click events can be handled via GTM click triggers (configured in GTM dashboard, not code). Scroll depth is a built-in GA4 event (auto-tracked when enhanced measurement is enabled in GA4). So only `generate_lead` needs code-level implementation.
