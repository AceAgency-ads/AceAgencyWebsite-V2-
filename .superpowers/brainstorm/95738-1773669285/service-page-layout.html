Service Detail Page — Section Order

How should the new sections (testimonials, portfolio, case studies) fit into the existing service page layout?

A

Social Proof After Features

Group all trust signals together in the middle of the page, before the process section.

1. ServiceHero — breadcrumbs, icon, title
2. HeroTransition — definition paragraph
3. ServiceFeatures — benefits grid
4. 📸 Portfolio Slider — screenshot gallery + visit site
5. ⭐ Testimonials — tagged testimonials slider
6. 📊 Case Study Results — photo + metric + 2 CTAs slider
7. ServiceProcess — methodology steps
8. ServiceStats — key metrics
9. ServiceFAQ — accordion
10. ServiceCTA — call to action

Pros

  • Social proof grouped = strong trust block
  • User sees proof before committing to read process

Cons

  • 3 sliders back-to-back could feel repetitive
B

Interleaved — Proof Between Logic

Spread social proof across the page so each logical section is followed by evidence.

1. ServiceHero — breadcrumbs, icon, title
2. HeroTransition — definition paragraph
3. ServiceFeatures — benefits grid
4. 📸 Portfolio Slider — "see what we've built"
5. ServiceProcess — methodology steps
6. 📊 Case Study Results — "here's what happened"
7. ServiceStats — key metrics
8. ⭐ Testimonials — "hear from clients"
9. ServiceFAQ — accordion
10. ServiceCTA — call to action

Pros

  • Narrative flow: features → portfolio → process → results → testimonials
  • Each proof type reinforces the section before it
  • No slider fatigue

Cons

  • Page gets longer
C

Bottom Proof Stack

Keep existing page untouched, add all new sections before FAQ/CTA at the bottom.

1. ServiceHero — breadcrumbs, icon, title
2. HeroTransition — definition paragraph
3. ServiceFeatures — benefits grid
4. ServiceProcess — methodology steps
5. ServiceStats — key metrics
6. 📸 Portfolio Slider — screenshot gallery
7. 📊 Case Study Results — results slider
8. ⭐ Testimonials — tagged testimonials
9. ServiceFAQ — accordion
10. ServiceCTA — call to action

Pros

  • Minimal disruption to existing page
  • Proof stacks before CTA = conversion push

Cons

  • User has to scroll far to see any social proof
  • May bounce before reaching it
